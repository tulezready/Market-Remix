# MaketPles ENB

Official online marketplace for small and medium enterprises in East New Britain Province, Papua New Guinea.

Built for the **Division of Commerce & Industry**, East New Britain Provincial Administration.

> **Status: connected, catalogue mode.** The site runs on a free Supabase project (Sydney). The Shop reads live listings (currently sample businesses), checkout places real orders paid through an agent or by bank transfer, and `register.html` / `admin.html` use the same database. Card payment waits on a gateway — see `docs/payments.md`. Plan: `docs/roadmap.md`.

## How the pieces fit together

```
                        ┌──────────────────────┐
   Business applies ──▶ │   register.html      │
   on the web           └──────────┬───────────┘
                                   │
   Officer registers    ┌──────────▼───────────┐
   at conference    ──▶ │  tools/intake.html   │  (works offline)
   or in the field      └──────────┬───────────┘
                                   │
                        ┌──────────▼───────────┐
                        │     admin.html       │  Division approves
                        │  approvals + review  │  businesses and listings
                        └──────────┬───────────┘
                                   │
                   ┌───────────────┴───────────────┐
                   ▼                               ▼
          ┌─────────────────┐            ┌──────────────────┐
          │  seller.html    │            │   index.html     │
          │  SME manages    │───────────▶│  buyers browse   │
          │  own listings   │  approved  │  and order       │
          └─────────────────┘  listings  └──────────────────┘
```

**Two doors in, one queue.** A business can apply for itself on the web, or be registered by an officer using the intake tool. Both land in the same review queue in the Division panel. Nothing reaches buyers until the Division approves it.

## Screen sizes

Every page adapts from a 320px phone through to a wide desktop. The layout steps
rather than jumping straight from desktop to mobile:

| Width | What changes |
|---|---|
| 1500px+ | Marketplace shows five products per row |
| 1180px | Tighter spacing, narrower search field |
| 1024px | Main nav collapses, three products per row |
| 860px | Single-column sections, sidebar becomes a top strip |
| 640px | Two products per row, basket and checkout become full-screen sheets |
| 400px | Single column throughout |

On phones the dashboard tables stop scrolling sideways and stack into cards
instead, each labelled so a bare figure still makes sense. Form fields are set
to 16px on small screens because iOS silently zooms the page when a smaller
field is focused. Touch devices get larger tap targets and lose the hover-only
effects. Notched screens are handled with `viewport-fit=cover` and safe-area
padding on anything anchored to the bottom of the screen.

## Running it locally

Everything is plain HTML, CSS and JavaScript. No build step, no dependencies.

```bash
# from the repo root
python3 -m http.server 8000
```

Then open <http://localhost:8000>.

A local server is needed rather than opening the files directly, because `index.html` fetches `data.json`.

## Publishing to GitHub Pages

1. Push this repository to GitHub.
2. **Settings → Pages → Source: Deploy from a branch**, branch `main`, folder `/ (root)`.
3. The site appears at `https://<user>.github.io/<repo>/`.

Once the `.com.pg` domain is approved, add a `CNAME` file containing the domain and point the DNS at GitHub Pages.

## Updating the marketplace content

No code editing required.

1. Open `tools/intake.html` and enter businesses and products.
2. Go to **Export & backup → Download data.json**.
3. Replace `data.json` in this repository.
4. Put the photographs in `photos/`, using the exact filenames recorded during collection.
5. Commit and push. GitHub Pages redeploys automatically.

The homepage slideshow is built from any business ticked as **Featured** in the intake tool. Six to twelve works well.

### Photograph naming

Use `DISTRICT_Business_subject_01.jpg`, for example:

```
photos/KOKOPO_Vunamami_hero.jpg
photos/KOKOPO_Vunamami_cocoa_01.jpg
photos/GAZELLE_Toma_blouse_01.jpg
```

Landscape, at least 1800px wide for slideshow images, taken in daylight. Leave clear space on the left third of slideshow photographs — the headline sits there.

## Sending a business a link

Once Supabase is set up (see `docs/supabase-setup.md`), `register.html` becomes a
link you can send by SMS or WhatsApp:

```
https://<user>.github.io/<repo>/register.html
```

The business fills it in themselves — details, products, and photographs chosen
from their phone gallery. Photos are shrunk in the browser, renamed to
`District_Business_subject_01.jpg`, and filed under their reference number.
They get a reference like `ENB-A1000` at the end.

Applications land in `seller_applications` for the Division to review. The
applicant cannot read anything back, including their own submission.

Until the two Supabase values are filled into `register.html`, the form shows an
amber preview bar and sends nothing — safe to share for comment, not for real use.

**On the Division's side**, `admin.html` → **Business applications** shows every
submission. Opening one loads the products and photographs the business
actually sent — each photo has a dropdown showing what it was tagged as
(business, front page, or a specific product), fixable before you approve.
Approving calls a database function that creates the business, moves its
photographs into the public bucket, and copies its products across as drafts
waiting in **Listing review**. Same amber-bar rule applies: until `admin.html`
has its own Supabase values filled in, it runs on sample data only.

## Collecting from a business in person

**Preferred: use the tool directly.** Open `tools/intake.html` on a phone or tablet,
sit with the business, and enter everything as you talk. Photographs are taken
straight into the tool with the camera — it shrinks them in the browser, so a 4MB
phone photo becomes about 150KB. Nothing needs typing in filenames.

It works with no signal. Entries are held on the device; take a **backup** before
you leave, since that file is the only copy.

Then: **Export → data.json**, drop it beside `index.html`, and the site shows that
business with its real photographs. The photographs are inside `data.json`, so
there is nothing else to copy.

> This suits a demonstration of a handful of businesses — roughly 2MB per business.
> Past about 12MB the tool will say so. For the full 35-business launch the
> photographs move out into files or Supabase storage.

**Fallback: paper.**

Print `tools/sme-form.pdf` — one page, A4, filled in with a pen. Useful when the
business would rather have something to hold, when a device is not practical, or
when several officers are collecting at once. Take two copies: one stays with the
business, one comes back to the Division.

It deliberately does **not** ask for bank details, TIN or IPA number. None of that
is needed to show a business on the site, and asking a stranger for bank details
on a platform that has not launched looks like a scam. Collect those at onboarding,
once the business has been approved.

The form ends with a signed permission to appear publicly. Get it signed before
using anyone's name or photographs in a demonstration.

Afterwards, type the paper form into `tools/intake.html`.

To change the form, edit `tools/build-form.py` and run it:

```bash
cd tools && python3 build-form.py
```

## The database

`db/schema.sql` is complete and has been tested against PostgreSQL 16. Run it once, top to bottom, in the Supabase SQL editor on a **new** project. It is safe to re-run.

It creates ten tables plus supporting views, and enforces these rules in the database itself rather than in the interface:

- Only businesses approved by the Division are visible to the public.
- Only listings set to `live` by the Division appear on the site. **A seller cannot publish their own listing.**
- **A seller cannot mark their own order as paid.** Payment status is set only after the payment gateway confirms it.
- A seller cannot see or edit another business's listings, orders or payouts.
- A seller cannot alter their own payout figures.
- Every price change is logged with a timestamp, giving the Division genuine provincial price data.
- Order lines store the price at the moment of sale, so later price changes never alter a completed order.

After running it:

1. Create a public storage bucket named `product-photos`.
2. Promote your own account:
   ```sql
   update profiles set role = 'division_admin' where id = '<your auth user id>';
   ```
3. Import collected data using the SQL export from the intake tool.

## Conventions worth keeping

- **Seven industries**, fixed: retail, wholesale, tailoring, arts & crafts, small scale downstream processing, fresh produce, food crops (rice & spices). These come from the Division's own SME listing — do not invent new ones.
- **Four districts**, fixed: Gazelle, Kokopo, Rabaul, Pomio.
- **Colours** are taken from the East New Britain provincial flag: red `#7E0F12`, green `#00702F`, black, on bone white.
- The **ENBPA logo** (`logo.svg`) is the Administration's own mark and is kept in this repository, so the site has no dependency on any other project. If the Administration supplies an updated official file, replace `logo.svg` and every page picks it up.
